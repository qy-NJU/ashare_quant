
# A股量化交易系统设计方案

## 一、总体架构设计理念

### 1.1 核心设计哲学

```
"数据是燃料，因子是引擎，模型是大脑，风控是刹车，执行是手脚"
```

整个系统围绕一条 **"数据→因子→模型→信号→组合→风控→执行"** 的流水线构建，但**不是一条单行道**——它应该是一个**闭环反馈系统**：实盘结果回流到回测评估中，模型根据新的市场数据持续进化。

### 1.2 分层架构总览

```
┌─────────────────────────────────────────────────────────────────┐
│                     📊 监控与运维层 (Monitoring)                    │
│             实时净值监控 · 异常告警 · 日志分析 · 可视化面板           │
├─────────────────────────────────────────────────────────────────┤
│                     🎯 执行层 (Execution)                          │
│            OMS订单管理 · 算法交易 · 券商接口 · 成交回报              │
├─────────────────────────────────────────────────────────────────┤
│                     🛡️ 风控层 (Risk Management)                   │
│       组合风险归因 · 行业集中度 · 回撤熔断 · 流动性检测 · 黑名单      │
├─────────────────────────────────────────────────────────────────┤
│                     📈 策略层 (Strategy Layer)                     │
│      信号融合 · 仓位管理 · 调仓节奏 · 止盈止损 · 动态仓位算法         │
├─────────────────────────────────────────────────────────────────┤
│                     🤖 强化学习层 (RL Layer)                        │

```

## 二、数据层（Data Layer）—— "燃料系统"

### 2.1 设计理念

数据的**完整性、准确性、时效性**决定了整个量化系统的天花板。A股市场的数据有特殊性：**涨跌停板导致的价格失真、T+1交收、分红除权复权、财报披露季节性**等，都需要在数据层就处理好。

### 2.2 数据分类体系

| 数据大类 | 具体内容 | 更新频率 | 优先级 |
|---------|---------|---------|-------|
| **行情数据** | 日K/周K/月K/60分钟/30分钟/5分钟/1分钟线 | 实时/日终 | ⭐⭐⭐⭐⭐ |
| **基本面数据** | 财报(ROE/PE/PB/现金流)、业绩预告、分红送转 | 季/年 | ⭐⭐⭐⭐ |
| **资金面数据** | 北向资金、融资融券、大宗交易、龙虎榜 | 日度 | ⭐⭐⭐⭐ |
| **另类数据** | 新闻情绪、公告NLP、行业研报、社交媒体舆情、机构调研 | 日度/实时 | ⭐⭐⭐ |
| **指数成分** | 沪深300/中证500/中证1000成分股及权重变更 | 半年调整 | ⭐⭐⭐ |
| **市场微观结构** | 逐笔成交、Level2盘口、委托簿快照 | 实时 | ⭐⭐ |

### 2.3 数据存储架构

```yaml
数据仓库设计:
  热存储 (Redis/内存):
    - 当日实时行情
    - 最新因子快照
    - 持仓/订单状态

  温存储 (PostgreSQL + TimescaleDB):
    - 结构化关系数据
    - 策略信号日志
    - 交易记录
    - 持仓历史
    - 元数据管理表

  冷存储 (Parquet 数据湖):
    - 历史K线 (按symbol分区)
    - 历史因子矩阵 (按trade_date分区)
    - 财报/事件数据
    - 模型checkpoint
```

### 2.4 数据质量保障

- **完整性校验**：每日自动检测全市场股票数据是否齐全，缺失自动补采
- **异常检测**：价格跳空超过阈值、成交量突变为零、复权因子异常
- **对齐校验**：不同数据源的同一字段交叉验证（如tushare与akshare的价格对比）
- **时间戳标准化**：统一为 `YYYYMMDD` 格式，处理节假日/交易日历
- **分红复权**：前复权/后复权双存，避免未来函数泄露

## 三、特征工程层（Feature Engineering）—— "引擎系统"

### 3.1 设计理念

> "Garbage in, Garbage out. 但好的特征比好的模型更重要。"

特征工程层的核心目标是：**从原始市场数据中，提取出对未来收益率具有稳定预测能力的特征**。我设计的特征是**多维度、多时间尺度、标准化处理**的立体体系。

### 3.2 因子分类体系（10维因子宇宙）

```
                    ┌── 趋势类 (Trend)
                    │   ├── 均线系统：SMA/EMA多头排列度、均线发散度、均线斜率
                    │   ├── 动量：ROC(5/10/20)、动量加速度(动量的一阶差分)
                    │   └── 通道：布林带宽、唐奇安通道突破比例
                    │
                    ├── 波动类 (Volatility)
                    │   ├── 真实波动幅度：ATR(14)、ATR占比
                    │   ├── 历史波动率：HV(5/10/20)、已实现波动率
                    │   └── 高低价差：振幅、影线占比
                    │
                    ├── 量价关系 (Volume-Price)
                    │   ├── 量价配合：OBV/量比/换手率
                    │   ├── 异常放量：量突破20日均量N倍的次数
                    │   └── 缩量特征：地量横盘天数、缩量程度
                    │
  10维度因子  ──────┼── 结构类 (Pattern/Structure)
                    │   ├── 蜡烛形态：红三兵/三只乌鸦/锤子线/吞没形态
                    │   ├── 价格结构：更高高/更低低序列、分形突破
                    │   └── 支撑阻力：整数关口距离、历史高低点距离
                    │
                    ├── 流动性 (Liquidity)
                    │   ├── Amihud非流动性指标、Roll价差估计
                    │   ├── 成交额分位数（在全市场中的位置）
                    │   └── 日内波动/换手稳定性
                    │
                    ├── 市场联动 (Market)
                    │   ├── Beta(滚动窗口)、CAPM Alpha
                    │   ├── 与沪深300/中证500/行业指数相关性
                    │   └── 上升/下跌市参与率（Up/Down Capture）
                    │
                    ├── 基本面 (Fundamental)
                    │   ├── 估值：PE/PB/PS分位数(历史3年/5年滚动)
                    │   ├── 盈利质量：ROE/ROIC/毛利率/净利率及趋势
                    │   ├── 成长性：营收YoY/净利YoY/经营现金流YoY
                    │   └── 财务健康：负债率/流动比率/利息保障倍数
 		    │
  		    ├── 资金流向 (Money Flow)
                    │   ├── 主力资金：超大单/大单净流入占比及趋势
                    │   ├── 北向资金：沪/深股通持股比例及变化
                    │   └── 融资融券：融资余额变化/融券余额占比
                    │
                    ├── 事件驱动 (Event-Driven)
                    │   ├── 龙虎榜：机构/游资净买额、上榜次数
                    │   ├── 业绩事件：超预期/低于预期幅度
                    │   └── 公告事件：高管增持/减持、股权激励、回购
                    │
                    └── 另类数据 (Alternative)
                        ├── 新闻情绪：NLP情感得分、新闻热度
                        ├── 机构调研：近期调研次数、参与机构数
                        └── 分析师预期：EPS预测修正方向、评级变化
```

### 3.3 特征预处理流水线

```python
# 严格按顺序执行，避免数据泄露
预处理流水线:
  第0步: 时间标记校验 —— 确保每行数据只有历史信息可用
  
  第1步: 僵尸股过滤
    - 近20日日均成交额 < 1000万 → 剔除（流动性陷阱）
    - 上市天数 < 120天 → 剔除（次新股噪音大）
    - ST/*ST/退市 → 剔除（基本面风险）
  
  第2步: 缺失值处理
    - 基本面因子：季度财报更新后前向填充(fill)，最多填充60天
    - 技术因子：NaN用截面中位数填充
    - 标记缺失率过高的因子（>30%）→ 自动排除
  
  第3步: 去极值 (Winsorization)
    - 在每期截面上，MAD(Median Absolute Deviation)法截尾
    - 阈值：中位数 ± 5*MAD
    - 不直接删样本，而是截断到边界值
  
  第4步: 标准化 (Standardization)
    - Z-Score标准化（截面）：消除各因子的量纲差异
    - 可选：Rank分位数标准化 → 对异常值更鲁棒
    - 重要：标准化在训练集和测试集上分别执行，训练集统计量用于测试集
  
  第5步: 正交化 (Optional)
    - 对高度相关的冗余因子做PCA或Lasso回归正交化
    - 行业中性化：因子值对行业哑变量回归，取残差
    - 市值中性化：因子值对对数市值回归，取残差
```

### 3.4 自动因子挖掘（进阶）

- **GPlearn遗传编程**：从基础运算符(+, -, *, /, abs, log, rank等)中自动演化出非线性因子表达式
- **因子IC分析自动化**：每天对所有因子计算截面Rank IC，自动检测失效因子(IC < 0.02持续20天)
- **因子动量衰减**：每个因子维护一个时效性权重，IC衰减越快权重越低

## 四、标签工程（Label Engineering）

### 4.1 设计理念

> "标签定义了模型的学习目标，错误的标签会让模型学到噪音而不是信号。"

A股的特点是**高噪音、强动量+反转交替、板块轮动快**，所以标签设计需要更加灵活和场景化。

### 4.2 多维度标签体系

```yaml
标签维度:
  
  1. 收益预测标签:
    a) 回归型:
       - 未来N日收益率 (forward_return_{N})
       - 未来N日超额收益(vs沪深300/行业指数)
       - 衰减加权收益 (越近的收益权重越大)
       适用模型: XGBoostRegressor, LightGBM, TabNet, DeepFM
    
    b) 分类型:
       - 二分类: 涨(1) / 跌(0), 阈值可配(如 >1%为涨)
       - 三分类: 涨(2)/平(1)/跌(0), 等频分桶或固定阈值
       - 截面排名: Top30%/Mid40%/Bottom30%
       适用模型: XGBoostClassifier, CatBoost, TabNet
    
    c) 排序型:
       - 截面收益率百分位 (0.0~1.0)
       - 适用模型: XGBoost rank:pairwise, LightGBM lambdarank
  
  2. 风控标签:
    a) 回撤预警:
       - 未来N日内是否出现超过M%的回撤 (二元分类)
    b) 尾部风险:
       - 未来N日收益率是否在截面中最差的10% (二元分类)
  
  3. 择时标签(大盘):
    a) 沪深300未来N日涨/跌/平
    b) 市场状态识别: 趋势市/震荡市/暴跌市 (三分类)
```

### 4.3 标签设计的高级考量

- **时变标签**：牛市用短周期(5日)，熊市用长周期(20日)追踪趋势
- **行业相对标签**：不是预测绝对涨幅，而是预测在同行业内排名 → 应对板块轮动
- **组合标签**：`最终标签 = 0.6*收益标签 + 0.3*风险标签 + 0.1*信息比率标签`

## 五、模型层（Model Layer）—— "大脑系统" 🔥核心

### 5.1 设计理念

> "没有完美的单一模型，只有合适的模型组合。"

我的设计核心理念是：**用集成学习的思想，构建多模型、多时间尺度的预测系统**。不同模型捕捉不同类型的市场规律，组合在一起才能对抗A股市场的复杂变化。

### 5.2 模型矩阵（多架构 × 多任务）

```yaml
模型矩阵:
  
  Level 1 —— 树模型家族 (擅长表格数据的非线性关系):
    XGBoost:
      用途: 主力模型，处理量价+技术因子
      优势: 速度快、正则化强、rank:pairwise天然适合排序
      # 关键参数
      目标函数: reg:squarederror / rank:pairwise / binary:logistic
      max_depth: 3-6 (浅树防止过拟合A股噪音)
      eta: 0.01-0.05 (低学习率确保稳定收敛)
      subsample/colsample: 0.7-0.8 (增加随机性)
      正则化: alpha(L1)=0.5, lambda(L2)=1.0
    
    LightGBM:
      用途: 处理基本面因子(类别特征多，如行业/概念)
      优势: 原生类别特征支持、leaf-wise生长更快
      # 关键参数
      num_leaves: 31-127
      min_child_samples: 50 (防止过拟合)
    
    CatBoost:
      用途: 处理高基数类别特征(如概念板块、申万3级行业)
      优势: 对类别特征无需手动编码，ordered boosting防过拟合
  
  Level 2 —— 深度学习家族 (捕捉高阶交互):
    TabNet:
      用途: 稀疏特征选择 + 注意力机制
      优势: 可解释的特征重要性mask、自步学习
      适用场景: 因子数量多(>200)时的自动特征选择
    
    DeepFM / xDeepFM:
      用途: 因子交互项的自动学习
      优势: FM层捕获二阶交互 + DNN层捕获高阶交互
      适用场景: 因子间存在强交互效应时
    
    时序Transformer:
      用途: 捕捉因子的时序演变模式(如因子动量)
      优势: 注意力机制可学习因子在不同时间点的权重变化
      输入: [Trading_Days × N_Features] 的时序矩阵
      注意: A股样本量相对不足，需要用预训练+微调策略
  
  Level 3 —— 时序模型家族 (专门处理价格序列):
    TFT (Temporal Fusion Transformer):
      用途: 多时间尺度预测 + 可解释性
      输入: 过去60天日K + 静态特征(行业/市值分组)
      输出: 未来5/10/20日收益分布(分位数预测)
    
    NBeats:
      用途: 纯时间序列预测
      优势: 基扩展(Basis Expansion)可解释趋势/季节分量
```

### 5.3 模型训练策略

```yaml
训练策略:
  
  a) 滚动窗口训练 (Rolling Window):
     设计:
       - 训练窗口: 过去3年 (~750个交易日)
       - 验证窗口: 后续3个月 (~60个交易日)
       - 测试窗口: 再后续3个月
       - 窗口每月向前滚动一次
     目的: 确保模型持续适应最新的市场风格
   
  b) 增量学习 (Incremental Learning):
     XGBoost: warm_start追加新树
     神经网络: 在新数据上finetune而非重新训练
     策略: 每日仅用新一天的数据做少量epoch更新
   
  c) 对抗训练 (Adversarial Validation):
     原理: 训练一个分类器区分"训练集"和"测试集"的样本
     目的: 检测训练/测试分布漂移，评估过拟合风险
     应用: 如果分类器AUC > 0.55，则模型面临严重的分布漂移
   
  d) 数据增强 (Data Augmentation for Time Series):
     方法: 
       - 时间扭曲(Time Warping): 随机拉伸/压缩时间轴
       - 窗口切片(Window Slicing): 从不同起点截取子序列
       - 因子噪声注入: 给因子值加微小高斯噪声
     目的: 增加A股有限样本量下的泛化能力
```

### 5.4 模型集成策略（Model Ensemble）🔥

这是我设计的核心亮点——**分层次、分场景的模型集成**：

```
                     ┌──────────────┐
                     │  最终预测信号  │
                     └──────┬───────┘
                            │
              ┌─────────────┼─────────────┐
              │             │             │
         ┌────▼────┐  ┌────▼────┐  ┌────▼────┐
         │ 趋势市场  │  │ 震荡市场  │  │ 暴跌市场  │
         │ 集成器   │  │ 集成器   │  │ 集成器   │
         └────┬────┘  └────┬────┘  └────┬────┘
              │             │             │
    ┌─────────┼───┐   ┌────┼─────┐   ┌───┼─────────┐
    │         │   │   │    │     │   │   │         │
  XGBoost LightGBM  TabNet DeepFM TFT  CatBoost 防御模型
  (rank)  (reg)     (cls)  (reg) (q50)(reg)   (risk_cls)
```

**集成公式：**

```
对每只股票i，在交易日t：

  Score(i,t) = Σ[w_m(t) * Score_m(i,t)]   (m ∈ 所有子模型)

  其中 w_m(t) 是动态权重，由以下因素决定：
    w_m(t) = softmax(
      α * IC_m(近期20日) +           # 近期预测能力
      β * IC_m(同风格20日) +         # 相似市场环境下表现
      γ * (1 - 波动率_m) +           # 惩罚不稳定模型
      δ * IC_m_decay                 # IC衰减速度惩罚
    )
```

### 5.5 模型评估体系

```yaml
评估指标分级:
  
  一级指标 (必看):
    - Rank IC (截面排名相关系数): 核心指标，>0.04即有效
    - Rank ICIR (IC信息比率): IC均值/IC标准差，>0.3良好
    
  二级指标 (分层看):
    - 分层回测收益单调性: 按预测分5组，第1组收益应 > 第5组收益
    - Top-K选股收益: 精确反映策略实际收益
    
  三级指标 (调试用):
    - 预测偏差(BIAS): 预测值均值 vs 真实值均值
    - 预测覆盖率: 预测值非空的样本比例
    - Factor Turnover: 因子值逐期自相关 → 判断是否过于敏感
```

## 五点五、强化学习层（Reinforcement Learning）—— "自适应决策增强"

### 5.5.1 设计理念

> "监督学习回答'哪个好'，强化学习回答'怎么办'。"

强化学习需要上，但**不要让它做选股**——选股是监督学习的强项（从海量横截面中找规律）。RL的真正价值在于：**给定候选池后，动态决定买多少、何时加减仓、何时清仓**。这是一个"high-level planning + low-level execution"的分工模式。

#### 为什么RL不适合做A股选股？

| 核心矛盾 | 具体表现 |
|----------|---------|
| **样本量不足** | A股有效历史≈15年/3750个交易日，RL需要百万级交互。差267倍 |
| **非平稳环境** | 2015年牛市和2024年熊市是不同世界，RL学到的是历史特定策略 |
| **动作空间爆炸** | 全市场5000只股票，每个离散动作是天文数字的组合 |
| **奖励函数悖论** | 每日PnL→赌博；夏普→稀疏奖励；增量夏普→噪声太大 |
| **Sim-to-Real Gap** | 回测中完美执行的策略，在实盘滑点/冲击/流动性约束下完全变样 |

#### 那RL适合做什么？

RL定位为**ML选股流水线的下游增强器**，具体承担三个角色：

```
┌──────────────────────────────────────────────┐
│              ML监督学习选股层                    │
│  输出: 每只股票未来收益预测分 (score_i)           │
│        Top-20候选池                            │
└──────────────────┬───────────────────────────┘
                   │
    ┌──────────────┼──────────────┐
    │              │              │
┌───▼────┐  ┌──────▼─────┐  ┌───▼──────────┐
│ 角色1   │  │  角色2      │  │  角色3        │
│仓位优化 │  │ 择时增强    │  │ 执行优化      │
│ 器RL   │  │ RL Agent   │  │ RL Agent     │
└───┬────┘  └──────┬─────┘  └───┬──────────┘
    │              │              │
    ▼              ▼              ▼
  每只配    延迟买入/    TWAP/VWAP
  多少仓位   提前卖出/   最优拆单
           加仓/减仓    节奏
```

### 5.5.2 RL核心架构设计

#### 算法选型：PPO + 离线预训练 + 在线微调

```yaml
选择PPO的理由:
  - 稳定性好: 相比于DQN/SAC, PPO的策略更新更平滑(裁剪损失)
  - 适合连续动作: 仓位比例是0~1的连续值
  - 离线可用: 先用历史数据训练, 再用模拟数据fine-tune
  - 行业验证: 在交易RL论文中PPO是主流选择

状态空间 (State):
  股票维度（对每只候选股i）:
    - ML预测得分 score_i
    - 当前持仓比例 position_i
    - 浮盈/浮亏比例 pnl_pct_i
    - 已持仓天数 hold_days_i
    - ATR(14) 波动率指标 atr_i
    - 距上次调仓天数 days_since_last_trade_i
  
  市场维度:
    - 沪深300近5日收益率 market_ret_5d
    - 全市场涨停/跌停家数 limit_up_count, limit_down_count
    - VIX类指标(已实现波动率)
    - 市场状态编码(趋势/震荡/暴跌 one-hot)
  
  组合维度:
    - 当前总仓位 total_position
    - 当前总浮盈/浮亏 total_pnl_pct
    - 可用现金比例 cash_ratio
    - 当前最大回撤 current_drawdown
    - 连续亏损/盈利天数 consecutive_loss_days

动作空间 (Action) - 仅对候选池中的股票:
  对每只候选股i的动作 a_i ∈ [-1.0, 1.0]:
    - > 0: 买入或加仓 (a_i * max_order_size)
    - = 0: 维持当前仓位
    - < 0: 卖出或减仓 (a_i * current_position)
  
  约束:
    - Σ买 ≤ 可用现金
    - Σ卖 ≤ 当前持仓
    - 单只上限 15%
    - 总仓位上限 80%

奖励函数 (Reward) - 经过精心设计的多目标组合:
  
  R_t = R_pnl + α*R_risk + β*R_efficiency + γ*R_consistency
  
  R_pnl (收益): 
    r_t = (portfolio_value_t - portfolio_value_{t-1}) / portfolio_value_{t-1}
    使用对数收益避免序列相关
  
  R_risk (风险惩罚):
    日回撤 > 2%:  penalty = -0.5
    日回撤 > 5%:  penalty = -2.0
    最大回撤创新高: penalty = -1.0
    # 不是线性惩罚，而是阶梯式，给模型明确的风险意识
  
  R_efficiency (效率):
    惩罚过度交易: -0.001 * |Δ仓位总和|
    奖励持仓稳定: +0.0005 * 未调仓日数
    # 降低换手率，节省手续费
  
  R_consistency (一致性):
    如果信号正确(ML预测涨且实际涨)但RL没买 → -0.1
    如果信号错误(ML预测涨但实际跌)且RL买了 → -0.2
    # 让RL学会信任/怀疑ML的时机判断
```

#### 训练策略

```yaml
阶段1: 离线预训练 (Offline RL / Batch RL)
  数据: 过去5年历史数据
  方法: 
    - 用历史ML信号 + 真实市场数据重放(replay)
    - 让RL在"如果当时这么操作会怎样"的模拟中学习
    - 关键: 不能用未来信息! 每步只看当时已知的数据
  目标: 让RL学到基本的仓位管理常识

阶段2: 对抗训练 (Adversarial Training)
  方法:
    - 人为构造极端市场场景(单日暴跌7%、连续阴跌10天等)
    - 在这些压力场景下训练RL的防守能力
  目标: 让RL见过"最坏的情况"

阶段3: 在线微调 (Online Fine-tuning)
  方法:
    - 实盘模拟中, 每周末用新增的一周数据进行微调
    - 不改变模型主体, 只调整最后的策略头(policy head)
  目标: 适应最新的市场风格

阶段4: 定期再平衡
  方法:
    - 每月检查RL模型是否"学坏了"(连续做出低质量决策)
    - 如果连续5笔决策亏损 > 按ML固定规则做, 则回退到上一版本
  目标: 安全第一, RL不能比规则策略差
```

### 5.5.3 RL与传统规则的协作模式

```python
# 混合决策: ML选股 → RL仓位 → 规则兜底
def 混合决策流程(交易日T):
    
    # Step 1: ML选出候选池和预测分(保持不变)
    候选池, 预测分 = ML监督模型.预测(因子矩阵)
    
    # Step 2: RL给出仓位建议
    if RL模型.可用 且 RL模型.近期表现_优于_规则基线:
        RL仓位建议 = RL模型.生成动作(状态=当前持仓+候选池+预测分+市场环境)
        目标仓位 = RL仓位建议
    else:
        # 回退到传统规则(波动率倒数加权等)
        目标仓位 = 规则仓位管理器.计算(候选池, 预测分)
    
    # Step 3: 规则层兜底校验(RL输出也必须过风控)
    for 股票, 仓位 in 目标仓位.items():
        if 仓位 > 单只上限:  仓位 = 单只上限
        if 股票 in 黑名单:   del 目标仓位[股票]
        if 股票.当日涨停:    del 目标仓位[股票]
    
    # Step 4: 如果RL驱动的总仓位 > 风控帽子，等比缩放
    if sum(目标仓位.values()) > 动态仓位上限:
        目标仓位 = 等比缩放(目标仓位, 动态仓位上限)
    
    return 目标仓位
```

### 5.5.4 RL的监控与安全机制

```yaml
安全网设计 (RL不能成为黑盒炸弹):

  ✅ 单笔最大亏损限制:
    RL单笔决策导致亏损 > 总资产2% → 自动熔断, 当天后续用规则替代RL
  
  ✅ 连续错误计数:
    连续5笔RL决策亏损 → RL降级为"仅建议不执行", 观察3天
  
  ✅ 行为边界约束:
    RL的仓位变化幅度不能超过规则版的±30%
    例如: 规则建议加仓10%, RL最多加到13%, 最少减到7%
  
  ✅ 每日复盘:
    RL每笔决策 vs 规则决策 → 生成绩效对比报告
    RL胜率 > 规则胜率 → 保持RL主导
    RL胜率 < 规则胜率持续5天 → 自动切换为规则主导
  
  ✅ A/B测试模式:
    50%资金用 RL决策
    50%资金用 规则决策
    每月对比绩效 → 统计检验是否有显著差异
```

## 六、策略层（Strategy Layer）—— "决策系统" 🔥核心

### 6.1 设计理念

> "模型告诉你什么东西可能涨，策略告诉你什么时候买、买多少、什么时候卖。"

策略层的三大核心任务：
1. **信号融合**：将多模型预测转化为可执行的交易信号
2. **仓位管理**：决定每只股票配置多少资金
3. **风险约束**：在极端市场下保护本金

### 6.2 信号生成流水线

```python
def 信号生成流程(交易日T):
    
    # Step 1: 多模型预测
    所有股票 = 获取全市场有效股票池()
    因子矩阵 = 因子流水线.转换(所有股票, 日期=T)
    
    预测结果 = {}
    for 模型 in [XGBoost, LightGBM, TabNet, DeepFM, TFT, CatBoost]:
        预测结果[模型.name] = 模型.预测(因子矩阵)
    
    # Step 2: 市场状态识别（决定集成权重）
    市场状态 = 市场状态识别器.判断(日期=T)
    # 输出: 'trending' | 'ranging' | 'crash' | 'rebound' | 'uncertain'
    
    模型权重 = 动态权重计算器.计算(预测结果, 市场状态)
    
    # Step 3: 加权融合
    最终得分 = sum(权重[m] * 预测结果[m] for m in 模型权重)
    
    # Step 4: 信号过滤
    最终得分 = 信号过滤器.过滤(
        最终得分,
        涨停剔除=True,      # 涨停买不到
        跌停剔除=False,     # 跌停不买但也不强卖
        流动性过滤=True,    # 成交额 < 2000万不买
        黑名单过滤=True,    # 自定义黑名单
    )
    
    # Step 5: 行业分布约束
    最终得分 = 行业约束.调整(最终得分)
    # 单行业不超过总仓位30%，避免行业过度集中
    
    return 最终得分.排序(降序)[:候选池大小]
```

### 6.3 仓位管理算法

这是我设计的**动态仓位三阶段模型**，借鉴了龙飞虎游资的仓位管理精髓：

```yaml
阶段一: 初始开仓 (首次买入)
  原则: 试探性建仓，验证模型判断
  规则:
    - 单只股票初始仓位: 目标总仓位 / (top_k * 2)
    - 即：如果top_k=5，总仓位目标60%，则每只初始6%
    - 永远不要一次性满仓
  
阶段二: 正常管理 (持仓常规调整)
  调仓触发条件 (满足任一即触发):
    a) 定期调仓: 每3个交易日重新评估 (降低交易成本)
    b) 信号调仓: 某股票预测得分排名跌出 top_30%
    c) 止损调仓: 触发ATR自适应止损线
    d) 止盈调仓: 触发移动止盈线
    e) 风控调仓: 大盘触发熔断指标
  
  权重分配方法 (三选一):
    a) 等权: w_i = 1/N  (最简单，表现不差)
    b) 得分加权: w_i = softmax(score_i) * target_ratio  (信任模型)
    c) 波动率倒数: w_i = (1/σ_i) / Σ(1/σ_j) * target_ratio  (风控优先)
    
    推荐: 默认波动率倒数加权 + 单只上限15%
  
阶段三: 风控降仓 (极端情况)
  触发条件:
    1. 持仓亏损股数 > 总持仓的50% → "逆风期"
       → 停止新开仓，总仓位压降至30%
    2. 连续3笔止损 → "连亏期"
       → 总仓位降至20%，每只仓位减半
    3. 沪深300连续3日在MA200下方 → "系统性风险"
       → 总仓位降至10%或空仓
    4. 全市场跌停数 > 50只 → "恐慌期"
       → 立即清掉所有盈利仓，保留深度亏损仓等反弹
```

### 6.4 止盈止损系统

```yaml
多层止盈止损体系:
  
  Layer 1 —— ATR自适应止损（个股级别）:
    原理: 每只股票的波动性格不同
    计算: 
      ATR(14) = 过去14天真实波动幅度的均值
      止损价 = 成本价 - N × ATR(14)
      N的选择: 普通2.5, 激进3.5, 保守1.5
    优势: 高波动股给更多空间，低波动股紧贴止损
    
  Layer 2 —— 移动止盈（个股级别）:
    激活条件: 浮盈 > 15%
    规则: 从最高点回撤8% 就止盈
    效果: 锁住大部分利润，让利润充分奔跑
  
  Layer 3 —— 时间止损（个股级别）:
    规则: 持仓超过20个交易日仍亏损 → 强制清仓
    理念: "时间是最好的试金石"
  
  Layer 4 —— 组合止损（组合级别）:
    日回撤: 单日亏损 > 总资产的5% → 强制平掉所有当日下跌超过3%的仓位
    周回撤: 周亏损 > 总资产的8% → 仓位减半进入防守
    最大回撤: 从最高点回撤 > 15% → 全线清仓, 暂停交易3天
  
  Layer 5 —— 大盘熔断（宏观级别）:
    规则: 沪深300单日跌 > 5% → 下午2:50前清仓
    理念: 系统性风险下，个股Alpha会完全被Beta淹没
```

### 6.5 多策略并行架构

```yaml
策略矩阵 (同时运行, 相互独立):

  主策略: ML多因子选股 (机器学习驱动)
    描述: 每日预测 → Top-K选股 → 等权/波动率加权
    仓位: 60%总仓位目标
    风格: 中短线, 3-5天调仓
    
  辅策略1: 事件驱动策略
    描述: 龙虎榜跟随、业绩超预期买入、高送转博弈
    仓位: 20%总仓位目标
    风格: 持有1-5天
    
  辅策略2: 可转债轮动 (低相关)
    描述: 双低策略(低价格+低溢价率)轮动
    仓位: 20%总仓位目标
    风格: 周度调仓
    目的: 与股票策略低相关性, 平滑组合曲线
    
  资金隔离原则:
    每个策略独立核算，互不侵犯资金池
    总风控层统一监控，任一策略触发风控只影响该策略
```

## 七、回测层（Backtest Engine）—— "检验系统"

### 7.1 设计理念

> "回测做得好可能是忽悠，回测做不好一定不能实战。"

回测的核心不是跑出一个漂亮曲线，而是**尽可能真实地模拟实盘交易中会遇到的各种摩擦**。

### 7.2 完整的T+1事件驱动引擎

```yaml
回测引擎特性:
  
  A股特有规则:
    ✅ T+1: 今日收盘信号 → 明日开盘买入，明日不能卖今日买的
    ✅ 涨跌停:
        - 科创板+/−20%, 创业板+/−20%, 主板+/−10%, 北交所+/−30%
        - 涨停: 买不进 (从候选池剔除)
        - 涨停打开: 可买但优先低
        - 跌停: 卖不掉 (持仓锁定到次日)
    ✅ ST/*ST: 涨跌停幅度+/−5%
    ✅ 日内价格模拟: 开盘价→最高价→最低价→收盘价的bar内路径
    
  交易摩擦:
    ✅ 佣金: 万3 (买卖双边)
    ✅ 印花税: 千0.5 (仅卖出)
    ✅ 过户费: 十万分之一
    ✅ 滑点: 
        - 买入滑点: +0.1% (买盘冲击)
        - 卖出滑点: −0.1% (卖盘冲击)
        - 市值<30亿小票: 滑点×3
    ✅ 市场冲击: 单笔成交额 > 日均成交额的5% → 无法全部成交
    
  进阶特性:
    ✅ 成交量约束: 单只股票当日成交量必须足够容纳目标仓位
    ✅ 停牌处理: 停牌日持仓冻结, 复牌后第一个交易日处理
    ✅ 分红处理: 现金分红记入现金, 送转股调整持仓数量
    ✅ 打新: 模拟打新中签收益 (真实A股打新收益不可忽略)
```

### 7.3 回测评估体系

```yaml
核心指标 (必须全部达标):
  年化收益率: > 15%
  夏普比率: > 1.2
  最大回撤: < 15%
  卡玛比率(年化收益/最大回撤): > 1.5
  胜率: > 55%
  盈亏比: > 1.8
  月度胜率: > 60%
  
诊断指标 (帮助优化):
  换手率(单边): 15% ~ 40%为合理
  容量测算: 策略在多大资金规模下开始衰减
  市场环境切片:
    - 牛市中收益 (应跑不赢指数但绝对收益好)
    - 熊市中收益 (应大幅跑赢指数、回撤小于指数)
    - 震荡中收益 (Alpha的主要来源)
  
防过拟合检查:
  ✅ 滚动窗口交叉验证 (不是简单的单次train/test split)
  ✅ 参数敏感度分析: 参数微调5%，结果波动不超过20%
  ✅ 随机打乱标签测试: 打乱后策略收益应接近0
  ✅ 样本外测试: 至少6个月完全未见过的数据
```

## 八、风控层（Risk Management）—— "刹车系统"

### 8.1 设计理念

> "风险控制不是在出事后才启动，而是在每一笔交易前就已经在运行。"

### 8.2 事前风控（开仓前）

```yaml
交易前检查清单:
  
  ✅ 个股层面:
    - 是否ST/*ST/退市整理 → 禁止买入
    - 是否当日涨停 → 禁止买入
    - 成交额 < 2000万 → 禁止买入 (流动性)
    - 是否存在重大利空公告 → 警告/禁止
    - 是否属于黑名单 → 禁止
  
  ✅ 组合层面:
    - 开仓后该行业占比是否 > 30% → 调整至30%以内
    - 开仓后总仓位是否 > 目标仓位 → 按比例缩减
    - 开仓后是否超过最大持股数 → 替换最低分持股
    - 与现有持仓是否有同一板块 > 2只 → 仅保留最高分1只
  
  ✅ 市场层面:
    - 大盘是否触发熔断/降仓信号 → 禁止所有新开仓
    - 开盘前是否有重大宏观事件 → 推迟开仓至10:30
```

### 8.3 事中风控（持仓中）

```yaml
实时监控:
  
  个股价差监控:
    - 日内跌幅 > 7% → 触发紧急止损
    - 盘中触及跌停 → 排队卖出(第二天失败则第三天市价)
    
  组合实时监控:
    - 总资产日内回撤 > 3% → 平掉所有当日跌幅 > 5%的仓位
    - 总资产日内回撤 > 5% → 全线减仓50%
    
  异常检测:
    - 某只股票成交量异常放大(>日均量5倍) → 减仓50%
    - 某只股票与大盘走势极度背离 → 标记观察
```

### 8.4 事后风控（收市后）

```yaml
每日盘后分析:
  
  组合风险归因:
    - Brinson归因: 行业配置贡献 vs 选股贡献
    - 因子暴露分析: 当前组合在各因子上的暴露
    - VaR计算: 99%置信度下明日的最大可能亏损
    
  策略评估:
    - 今日信号与实际走势对比
    - 如果信号正确但未赚钱 → 执行问题
    - 如果信号错误 → 模型预警
```

## 九、执行层（Execution）—— "手足系统"

### 9.1 OMS订单管理系统

```yaml
订单管理:
  
  订单生命周期:
    信号生成 → 订单创建 → 风控校验 → 发送券商 → 
    成交回报 → 持仓更新 → 绩效归因
    
  订单类型:
    - 限价单 (Limit Order): 指定价格，按最新盘口±2个tick挂单
    - 市价单 (Market Order): 以当前卖一/买一成交 (流动性好时)
    - TWAP (时间加权均价): 将大单拆分为多个小单，30分钟内均匀发出
    - VWAP (成交量加权均价): 跟随市场成交量节奏发单 (大资金必需)
    
  订单状态机:
    PENDING → SUBMITTED → PARTIAL_FILLED → FILLED
                     ↘ REJECTED  (retry or cancel)
                     ↘ CANCELLED (人工取消)
```

```yaml
    - 大单(>5%日均量): 需要拆成多天执行，每天TWAP

    - 未成交单需在14:55前完成或撤单
```

## 十一、完整的调度与执行流程

### 11.1 每日工作流

```
15:00 ─ 收盘，开始等待数据源更新
  ├── tushare 日K线数据通常在 17:30 之后才完成更新
  ├── 龙虎榜数据约 17:00-18:00 陆续发布
  ├── 北向资金数据约 18:00-19:00 发布
  └── 融资融券数据约 次日 9:00 前发布（T+1数据）

  ⚠️ 关键时序约束:
     - 最早可获取有效日线数据的时间: 17:30
     - 部分数据源（如融资融券）有 T+1 延迟
     - 因此将主计算流程安排在 18:00 之后启动

18:00 ─ 数据采集
  ├── 18:00 下载当日全市场日K线数据 (tushare/akshare)
  ├── 18:05 下载当日龙虎榜、北向资金、大宗交易
  ├── 18:10 增量更新融资融券数据（T+1，更新上一交易日数据）

  ├── 18:25 对所有股票计算最新因子值

  ├── 18:45 行业中性化 + 市值中性化处理
  ├── 18:50 生成次日预测所需特征矩阵
  └── 18:55 保存特征快照（含版本号，便于回溯）

19:00 ─ 模型预测
  ├── 19:00 各子模型独立预测（XGBoost/LightGBM/CatBoost/TabNet 并行）
  ├── 19:10 市场状态识别器判断（趋势/震荡/暴跌）
```

## 十二、从现有系统的升级路径

当前系统已经有了坚实的基础：完整的数据层、11个因子模块、XGBoost模型、专业回测引擎、龙飞虎仓位管理。我的设计是在此基础上的**渐进式进化**：

| 模块 | 当前状态 | 升级方向 | 优先级 |
|------|---------|---------|--------|
| 数据层 | Parquet本地湖 | 增加TimescaleDB时序库、数据质量自动校验 | ⭐⭐⭐ |
| 因子 | 11个手工因子 | 增加GPlearn自动因子挖掘、因子IC自动监控 | ⭐⭐⭐ |
| 模型 | 单一XGBoost | 增加LightGBM/CatBoost集成、增加TabNet | ⭐⭐⭐⭐⭐ |
| **RL** | **无** | **PPO仓位优化器 + 离线预训练 + 在线微调 + 安全网** | **⭐⭐⭐⭐** |
| 标签 | 多种类型可配 | 增加行业相对标签、风险预警标签 | ⭐⭐⭐⭐ |
| 策略 | 动态仓位+ATR止损 | 增加市场状态识别、多策略并行、RL仓位融合 | ⭐⭐⭐⭐⭐ |
| 回测 | 功能完善 | 增加滚动窗口交叉验证、参数敏感度分析 | ⭐⭐⭐ |
| 风控 | 策略内嵌 | 独立风控层、事前事中事后全覆盖 | ⭐⭐⭐⭐ |
| 执行 | 无 | OMS订单管理、TWAP/VWAP算法交易 | ⭐⭐ |
| 监控 | 无 | 实时监控面板、告警推送 | ⭐⭐⭐ |
| 因子 | 无行业中性化 | 行业中性化+市值中性化处理 | ⭐⭐⭐ |
